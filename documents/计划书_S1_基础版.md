## 五、关键技术要点

### 5.1 湿笔迹层（本期最关键实现）

```
落笔 → InkCanvas 湿层实时绘制（不进文档、不进撤销栈）
     → 抬笔 → Stroke.GetGeometry() → 转为 FreehandObject → 入文档 + 压栈
     → 触发重绘，湿层清除
```
要点：湿层与文档层**坐标对齐**；湿墨迹清除时机必须等文档层完成重绘，否则出现"抬手闪一下"（旧项目同类问题的常见表现）。

### 5.2 橡皮擦：按覆盖面积擦除 —— 用「遮罩保留」，**不碎片化**

> ⚠️ **需求澄清（2026-09-12）**：橡皮擦**只擦除覆盖面积内的部分**，**不是**按笔画或整对象删除。

> ⚠️ **实现路线澄清（用户提出，2026-09-12）**：**选择工具选中的是"笔画"**，而"擦除即把一笔切成多笔"会让选择工具的语义崩掉。
> 实测：一条 200 点笔迹被 10 个擦除圆覆盖后会变成 **11 个独立对象**；1200 点被 40 个圆覆盖 → **25 个**。
> **因此采用「遮罩保留 + 延迟烘焙」（ADR-18），不做立即碎片化。**

| 层 | 做法 |
|---|---|
| **模型** | 对象保留**原始点集 / 参数**，另存 `Erasures`（擦除圆的**世界坐标**列表） |
| **渲染** | `渲染几何 = 原几何 − 擦除遮罩`（`Geometry.Combine(g1, g2, GeometryCombineMode.Exclude, null)`）；**结果缓存**，仅在遮罩或几何变化时重算 |
| **命中测试** | 在**差集后的几何**上做 → 被擦掉的区域点不中 |
| **选中** | **永远选中"那一笔"整体**（含被擦除区域）→ 与选择工具语义一致 ✅ |
| **拖动** | 整条一起移动 |
| **撤销** | 一次擦除 = 一次遮罩追加 = **一条命令**（不是"1→N 替换"） |
| **延迟烘焙** | 遮罩数超阈值（如 32）或用户点「**切分为独立对象**」时，才真正切分成多个对象（S2 提供该操作） |
| **序列化** | 对象多一个 `erasures` 字段 |
| **几何形状** | **同样用遮罩**：保留参数化形状（直线/矩形/椭圆）+ 遮罩，渲染时差集 |

| 对象 | 擦除行为 |
|---|---|
| 自由画笔 | 遮罩差集（视觉上即"按覆盖面积切割"） |
| 几何形状（直线/矩形/椭圆） | 同上；**结果为空时删除对象** |
| 文本 / 公式 / 化学式 | **跳过**（`IsErasable = false`），只能选中后 Delete |
| 触摸 | 触点集做**单调链凸包** → **鞋带公式**求面积 → `diameter = clamp(√area × 1.6, 60, 420)` 屏幕像素 → 折算世界尺寸（**下限 60px**） |
| 手掌擦除 | 橡皮工具下，面积超阈值即视为手掌擦除（ADR-11） |

**实测代价（M0 已验证，`artifacts\poc-a-selftest.txt`）**

| 点数 | 擦除圆数 | 几何差集 |
|---:|---:|---:|
| 60 | 1 | 0.38 ms |
| 200 | 10 | 0.54 ms |
| 600 | 20 | 0.67 ms |
| 1200 | 40 | **1.07 ms** |

→ 最坏 **1.07 ms**，且仅在遮罩变化时重算一次 → 完全可行。

**必须写单元测试**：遮罩差集的空结果、孔洞、自交、矩阵不可逆、碎片阈值烘焙。
**待 M0 · PoC-B 补充**：更极端的退化用例（多块分离、孔洞、遮罩重叠）。
### 5.3 路径服务（数据自包含，无回退链）

```csharp
// 数据目录：固定为 <exe同级目录>\data\，没有回退链
DataRoot = Path.Combine(AppContext.BaseDirectory, "data");

// 不可写时：报错并进入只读模式，绝不静默降级到系统位置
if (!CanWrite(DataRoot)) → 提示「程序文件夹不可写，请把整个 WhiteBoard 文件夹复制到可写位置后重试」
                        → 只读模式（禁用自动保存与配置写入，顶部醒目提示）

// 硬性规则
// 1. 禁止任何盘符字面量或绝对路径；一律基于 AppContext.BaseDirectory 解析
// 2. 所有可写路径必须经 PathService 获取，禁止直接使用 %APPDATA% / %TEMP% / %LOCALAPPDATA%
// 3. 程序产生的所有数据文件必须落在 exe 同级目录或其子目录内（用户显式保存的画板文件除外）
```

### 5.4 保存路径与默认命名（依决策 D3）

| 场景 | 行为 |
|---|---|
| 用户点「保存」且已有路径 | 直接写回原路径（**可在程序文件夹外**，如 U 盘） |
| 用户点「保存」但**从未指定过路径** | **不弹阻塞对话框**，直接写 `<程序文件夹>\data\documents\<yyyyMMdd_HHmmss>.wb`，状态栏提示实际保存位置 |
| 用户点「另存为」 | 弹文件对话框，允许任意位置（U 盘 / 网络盘 / 其他分区）；用户取消 → 回到未指定状态 |
| 自动保存 | 只写 `<程序文件夹>\data\autosave\`，不打扰用户 |

**理由**：课堂上不能因为"选路径"打断讲课节奏；时间戳命名免去起名负担，且天然去重、便于按时间排序。

### 5.5 序列化与版本

`document.json` 顶层写入 `"schemaVersion": 1`，加载时做向后兼容分支；`.wb` 内附 `meta.json`（创建时间、应用版本、schemaVersion）。

**格式必须现在就为 S2 留扩展位**：
- 多态类型注册表机制（`[JsonPolymorphic]` + 类型判别字段）；

否则 S2 加图片对象、新形状、页面背景时会推翻 S1 的存储层。

### 5.6 湿/干笔迹外观（评审 Q1 —— 已由"改平滑风"解决）

**原问题**：湿笔迹由 `InkCanvas` 渲染、干笔迹由自研手绘渲染器渲染，两者笔尖模型不同，抬笔瞬间会"变样子"。**PoC-A 人工实测确认：差异非常明显。**

**决策（ADR-09）：笔迹与图形一律采用平滑风，放弃手绘抖动风。**

**M0 验证结果**（同一组 160 点 + 同一份 `DrawingAttributes`，逐像素比对）：

| 干笔迹渲染方式 | 与湿渲染的差异像素 | 占比 |
|---|---:|---:|
| `stroke.Draw(dc)` | **0** | **0.000%** |
| `dc.DrawGeometry(brush, null, stroke.GetGeometry())` | **0** | **0.000%** |
| `dc.DrawGeometry(null, pen, stroke.GetGeometry())`（几何描边） | 14 119 | 1.681% |

**采用方案**：
1. 文档中保存**原始点 + `DrawingAttributes`**；
2. 渲染时重建 `Stroke` → `GetGeometry()` → **几何填充**（`DrawGeometry(brush, null, geo)`）；
3. 几何构建后 `Freeze()` 缓存；平移缩放只换变换矩阵，不重建几何；
4. **不再需要淡入过渡**——抬笔时外观零突变。

> 几何描边方式（差 1.68%）不可用：`InkCanvas` 画的是**压感变宽的填充轮廓**，不是等宽描边。
> 几何构建耗时实测 ≈0 ms（一次构建、冻结复用），性能无忧。

**⚠️ 补充（人工核验发现的第二个问题）**：上表比的是"InkCanvas 渲染**已完成**笔迹"，**没有覆盖书写过程中的湿态**。
实际使用中发现：**抬笔前（湿态）比抬笔后（干态）粗糙** —— 原因是 `InkCanvas` 在书写过程中使用**增量廉价渲染**，抬笔才切换到拟合几何。

**修法**：**湿态也自绘**，与干态走同一条路径：
```
落笔 → 每帧 rebuild: 累积点 → Stroke → GetGeometry() → 填充 → InvalidateVisual
抬笔 → 点集不再变化 → 几何不再变化 → 外观零跳变
```
实测每帧重建代价（含 60Hz 帧预算占比）：

| 点数 | 重建耗时/帧 | 占帧预算 |
|---:|---:|---:|
| 60 | 0.11 ms | 0.6% |
| 300 | 0.23 ms | 1.4% |
| 600 | 0.36 ms | 2.2% |
| 1200 | 0.77 ms | 4.6% |
| 2000 | 0.83 ms | 5.0% |

→ **完全可行**，无需节流。

**架构含义**：**不再使用 `InkCanvas` 的自带湿渲染**（输入采集仍可由它或自建输入层完成），
湿/干/缩放/导出全部走我们自己的矢量管线，行为完全可控。

### 5.6.1 抗锯齿与无损放大（S2 需求）

### 5.6.1 抗锯齿与无损放大（S2 需求：无损放大 50 倍）

**已实测确认可行**（离屏渲染 + 逐像素分析，1200×700，带压感曲线）：

| 缩放 | 渲染耗时 | 笔迹像素 | **边缘过渡宽度** |
|---|---:|---:|---:|
| 1x | 2.4 ms | 2,568 | 3.95 px |
| 10x | 3.1 ms | 83,322 | 3.41 px |
| **50x** | 2.6 ms | 437,567 | **2.71 px**（1~3 px = 抗锯齿正常 ✅） |
| 对照组：位图缓存后放大 50 倍 | — | 26,613 | **190.09 px**（完全糊掉 ❌） |

**三条设计红线**：

1. **几何按世界坐标构建**，缩放平移只改变换矩阵 → 放大是**重绘**而非位图放大；
2. **禁止把画布缓存成固定分辨率位图**（上表对照组就是反例：边缘过渡 190 px vs 2.71 px）；
3. **抗锯齿保持开启**：`RenderOptions.EdgeMode = Unspecified`、`BitmapScalingMode = HighQuality`，
   关闭 `UseLayoutRounding` / `SnapsToDevicePixels`（避免像素对齐造成的边缘台阶）。

**笔宽必须按世界单位存储**（否则放大 50 倍时线宽不跟着变粗）。

导出高清图时用 `pixelsPerUnit` 参数提高渲染分辨率即可（S1 的导出已按此设计）。

### 5.8 双指手势与绘制冲突（评审 Q4）

> **规则：笔画进行中，第二根手指落下时——忽略第二指，直到笔画结束。**

理由：书写不被打断、防误触（手指或手掌搭在屏上是常态）。代价是"画到一半想缩放"必须先抬手。

### 5.9 撤销栈：每页独立（评审 Q5）

- **每页一个独立的撤销栈**；撤销/重做只作用于**当前页**；
- 切换页面时撤销/重做按钮的可用状态随之变化；切回该页可继续撤销该页历史；
- **切换页面本身不入栈**；
- 栈有上限（步数与总字节数取小），溢出时**丢弃最早的**（而非停止记录，否则用户会以为撤销坏了）；
- ⚠️ **连带冲突一**：S2 的跨页复制/移动在此语义下无法一次撤销，须按 `S1产品与技术评审.md` §4.1 **方案 A**（配对命令 + 自动切回源页）处理。S2 开工前必须确认。
- ⚠️ **连带冲突二（本期必须定）**：**"页面级操作"没有归属的栈**——新建页 / 复制页 / 删除页 / 追加导入都不属于任何单一页面的内容，在"每页独立栈"下无处安放。若硬塞进当前页的栈，用户会遭遇"在 A 页按 `Ctrl+Z`，结果删掉了一整页"的惊吓。

  **已定方案：页面级操作不进撤销栈，改用「确认 + 补偿入口」**（评审 R1 确认）
  | 操作 | 处理 |
  |---|---|
  | 新建页 / 复制页 | 无需撤销（无害操作，不需要就删掉） |
  | **删除指定页** | 入口在**页面目录**：每个缩略图提供**删除按钮**（见 §5.12）；点击后**确认对话框**；页面数据临时保留在"最近删除"中直到保存或关闭文档，可一键恢复 |
  | 追加导入 | 完成后显示**非阻塞提示条**「已追加 n 页 · 撤销」，点击即整体移除本次导入的页 |

  **配套规则（边界情况）**：
  - 文档**至少保留 1 页**：删除最后一页时自动补一个空白页；
  - 删除的是**当前页**时，自动跳到相邻页（优先前一页）；
  - "最近删除"仅保留在当前会话内（保存或关闭文档后清空）。

  这样既守住"撤销 = 当前页内容"的语义，又给了用户真实的后悔药。

### 5.10 主题色（评审 Q6）

**文件格式（由程序定义）**：源码内 `color.txt` 是**规范文件与默认值来源**（JSON 结构），构建时嵌入为内置默认值；运行时若存在 `<exe同级>\data\theme\color.txt` 则覆盖之。

```json
{
  "version": 1,
  "defaultPreset": "blackboard",
  "presets": [
    {
      "id": "blackboard", "name": "黑板",
      "backgroundType": "solid", "background": "#2F4F3A",
      "colors": [
        { "id": "white",  "name": "白笔", "value": "#F5F5F0" },
        { "id": "yellow", "name": "黄笔", "value": "#EED858" },
        { "id": "red",    "name": "红笔", "value": "#F47A6E" },
        { "id": "blue",   "name": "蓝笔", "value": "#6E9FE0" }
      ]
    }
  ]
}
```

- **为什么用 JSON 而不是原来的 CSS 自定义属性语法**：S2 起该文件要**保存用户的预设**（程序写入、多套预设、可命名、可能带背景类型），需要结构化与可扩展；CSS 变量语法是给样式表用的，不适合程序读写同一文件。
- **红、蓝已调亮**（原 `#E04D40` 2.3:1 / `#5485C9` 2.4:1 → **`#F47A6E` 3.4:1 / `#6E9FE0` 3.4:1**，均达 3:1 图形下限）。白 8.4:1、黄 6.4:1 保持不变。
- **健壮性**：解析器必须容忍缺项、未知字段、类型错误；**任何解析失败一律回退内置默认值**，绝不影响启动（需单元测试覆盖：空文件、坏 JSON、缺 colors、非法色值）。
- **文件编码**（实测踩到的坑，已定为全局约定）：主题/配置/说明文件含中文，**写入侧统一 UTF-8**，**读取侧宽容兼容**——
  1. 先按字节读取，**剥离 UTF-8 BOM**；
  2. **优先 UTF-8 严格解码**（用户侧首选）；
  3. 失败则回退**系统 ANSI 编码**（中文用户用记事本"另存为 ANSI"会产生 GBK 文件）；
  4. 仍失败 → 用内置默认值。
  > 若不做这一步，用户在中文环境下编辑该文件后，程序可能因编码不符而整体回退默认，用户会以为"改了没用"。
  > 写入时**带 BOM**（Windows 记事本与其他编辑器兼容性最好）。
- S1 **只做纯色背景**（`backgroundType: "solid"`），字段先留好；**S2 扩背景类型与预设管理**。

### 5.11 笔宽三档（细 / 中 / 粗）

- **三档固定值（世界单位，随视口缩放）**：**细 3 / 中 6 / 粗 10**（ADR-15）；理由见 `需求对照与差异清单.md` §六 —— 实测 <1.5 px 发虚、≥2 px 才实心均匀；
- **屏幕渲染宽度下限 2 px**：`世界宽度 × 缩放 < 2 px` 时按 2 px 渲染，避免缩小视图时发虚；放大时不受影响（无损放大仍成立）；
- **控件形态**：三枚**图形按钮**，每个按钮内绘制一条对应粗细的线条（或圆点），**点击图形即选中**，选中态有明显高亮；
- 笔迹对象记录自己的笔宽，与当前选择解耦（改选择不影响已画内容）；
- 数据模型里笔宽为**可扩展字段**（S2 加自定义与预设时不改结构）。

### 5.12 页面导航与目录

- **右侧页面目录**：缩略图列表 + 页码；点击跳转；当前页高亮；页数多时滚动流畅（缩略图脏页 + 500 ms 防抖，见 T13）；
- **每个缩略图提供「删除」按钮**（评审 R1 要求）：点击 → **确认对话框** → 删除该页；被删页面进入"最近删除"，可一键恢复（见 §5.9 边界规则）；
- **上一页 / 下一页按钮**：工具栏可见；到首/尾页时按钮置灰；
- 与键盘翻页（PageUp/PageDown/←→）行为一致。

### 5.13 整体打包与追加导入（n 页 = 1 个文件）

**保存 / 打开**
- **保存**：把**整个文档的全部页面**打包为单个 `.wb`（ZIP：`document.json` 含 `Page[]` + `images/` + `meta.json`）；
- **打开**：一次恢复全部 n 页（页面数、每页对象、每页独立视口、当前页索引），**替换当前文档**；
- **验收**：A6/A20 的往返一致性必须覆盖"多页 + 每页独立视口 + 当前页索引"。

**追加导入**（"文件 → 导入页面…"）

| 项 | 规则 |
|---|---|
| 入口 | 菜单「文件 → 导入页面…」，选择另一个 `.wb` |
| 行为 | 读取源文件的**全部页面**，**追加到当前文档末尾**；**不修改源文件**；文档标题与已存路径不变 |
| 对象 Id | 导入时**全部重新生成**，避免与当前文档冲突 |
| 图片资源 Id | **重映射**：内容相同的资源可复用，否则重命名并复制进当前文档的 `images/` |
| 视口 | 保留每页**自带的视口**（导入页保留原样，不继承当前页缩放） |
| 导入后 | **自动跳转到第一张新导入的页**，并在状态栏提示「已追加 n 页，当前共 m 页」 |
| 失败处理 | 源文件损坏 / `schemaVersion` 不支持 → **给出可读中文原因，整体不导入**（不做部分导入） |
| 与"打开"的区别 | **打开 = 替换整个文档；导入 = 追加页到当前文档** |

> ⚠️ **追加导入与撤销栈的关系**见 §5.9 与待确认项（页面级操作的归属）。

### 8.1 专项评估：S1 是否纳入跨页复制/移动？

> 结论：**S1 不做，推迟到 S2**。理由如下。

**支持放进 S1 的理由**
- 老师可能想把某页的一张图挪到另一页；
- 早做可以尽早暴露撤销栈的设计问题。

**建议推迟的理由（权重更高）**

| # | 理由 | 说明 |
|---|---|---|
| 1 | **课堂刚需度低** | S1 已纳入"复制当前页"，老师的真实需求"这页要再讲一遍"已解决；**把单个对象移到另一页不是课堂高频动作** |
| 2 | **它是"每页独立撤销栈"语义下最复杂的部分** | 需要配对命令 + 跨页回滚 + 自动切页 + 与"切页不入栈"的规则交互；正确性需要专门的测试面（配对一致性、部分失败回滚、撤销顺序） |
| 3 | **它依赖两个尚未稳定的地基** | 页面管理与撤销栈都要在 S1 才建成；在它们刚成型时立刻叠加跨页事务，返工风险高 |
| 4 | **交互载体未定** | 原设计是"拖到右侧缩略图 + 修饰键"，属跨控件拖放；S1 同时做拖放手势 + 配对命令，风险叠加 |
| 5 | **挤压缓冲** | 跨页操作 + 配对命令机制约 4 人日（含测试），会把 S1 缓冲从 19.5% 压到约 15.5%，而 M0 一旦需要调整基线就没有余量了 |

**风险量化对比**

| 选择 | 代价 | 收益 | 风险 |
|---|---|---|---|
| S1 做 | +4 人日，S1 缓冲 → ~15.5% | 提前 4 周可用 | 中（跨页事务在未稳定地基上叠加） |
| **S1 不做（采用）** | 该功能晚 4 周（S2 交付） | 保住缓冲与地基质量 | 低 |

**S2 实施时的强制约束**：必须用**方案 A**——源页与目标页各记一条命令并**配对互引**，撤销任一条时同时回滚两侧，并自动切回源页。否则一次 `Ctrl+Z` 只撤销一半，会出现对象重复或两边都消失的不一致状态。
