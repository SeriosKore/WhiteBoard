# 白板开发总路线

> 版本 v1.0 · 本文档是**唯一技术基线**，后续各期计划书均以本文档为准
> 目标平台：**Windows 10 / Windows 11 x64**（**两者都必须可用**，同一份自包含产物）· 面向学校机房 / 教室一体机 / 家庭电脑

## 一、四条硬约束（全部已锁定，任何设计不得违反）

| # | 约束 | 来源 | 对本项目的影响 |
|---|---|---|---|
| **C1** | **免环境部署** | 客户 | 不装运行时、不装安装包、免管理员、离线可用；**不得依赖目标机未预装的组件**（含 VC++ 可再发行组件） |
| **C2** | **应用与插件均不得写入注册表** | 客户 | 配置只落文件；插件沙箱在解析层拒绝注册表 API |
| **C3** | **数据自包含** | 客户 | 程序产生的**所有数据文件**必须位于 **exe 同级目录或其子目录**内（**用户显式保存的画板文件除外**） |
| **C4** | **插件生态开放给第三方** | 客户 | 第三方走**沙箱通道**，官方走**进程内通道** |

> 说明：C1 与 C3 合起来就是"**绿色便携**"——整个文件夹拷到任意位置即可运行，不依赖机器上装了什么、也不往机器别处留东西。

### 1.1 关于"不得写入注册表"的验收口径（必须写进合同）

> **任何带图形界面的 exe 一经启动，Windows 自身就会写注册表**：`HKCU\Software\Classes\Local Settings\Software\Microsoft\Windows\Shell\MUICache`（[证据](https://artefacts.help/windows_registry_muicache.html)）。此外还有 ShimCache/Amcache（HKLM）、UserAssist、Prefetch。这些是**操作系统行为，应用无法阻止**。

因此验收口径定为三条：

1. 应用与插件**不得创建、修改、删除任何注册表键值**（HKLM/HKCU 均不得），系统自身执行痕迹除外；
2. 应用**不得依赖注册表**存储任何配置、状态或授权（清空注册表后功能完全不受影响）；
3. 应用**不需要管理员权限**。

## 二、技术选型（已锁定）

| 项 | 决定 | 理由 |
|---|---|---|
| **语言** | **C# 12** | 语言本身不是上次失败的原因 |
| **框架** | **WPF** | 直连 D3D，`InkCanvas` 提供低延迟湿笔迹 + 压感；实测 Avalonia 比 WPF 落后 1~2 帧（最多 5 帧），属架构性延迟（[来源](https://blog.lindexi.com/post/Avalonia-%E7%AC%94%E8%BF%B9%E6%B8%B2%E6%9F%93%E5%A4%AA%E6%85%A2%E4%BA%86-%E7%94%A8-WPF-%E5%81%9A%E5%8A%A0%E9%80%9F%E5%B1%82.html)） |
| **运行时** | **.NET 10（`net10.0-windows`）+ 自包含** | 彻底不关心目标机装了什么 .NET；且只有 .NET 8+ 才能在 ALC 解析层拒绝 `Microsoft.Win32.Registry`（C2） |
| **发行形态** | **自包含 + 单文件夹**（`PublishSingleFile=false`） | 单文件会把原生库解压到 `%TEMP%`（[微软文档](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/unpackage-winui-app?tabs=csharp)）——启动慢、且在系统位置留下解压物，破坏绿色自包含；单文件夹启动快、可完整审计 |
| **第三方原生库** | **一律不引入（零 native 依赖）** | C1 要求：不依赖目标机未预装的组件。图形/编码/压缩/JSON 全部用 .NET 与 WPF 内置能力 |
| **图像编解码** | **WIC**（PNG/JPG/BMP/GIF/TIFF 内置） | 零依赖。**WebP 不保证**（Win10 需商店扩展，离线机房不可靠）→ 列为可选，默认不支持 |
| **笔迹风格** | **平滑风**（**放弃**原需求的手绘抖动风） | ⭐ **M0 实测决策**：平滑风下可用 `Stroke.GetGeometry()` 填充渲染干笔迹，与 `InkCanvas` 湿笔迹**逐像素完全一致（0 差异）**，抬笔时外观零突变；同时**删掉自研抖动/平滑算法**，省工省风险。详见 `M0进展报告.md` §六-C |
| **湿笔迹渲染** | **自绘**（每帧重建 `Stroke` 几何并填充），**不用 `InkCanvas` 自带的湿渲染** | ⭐ **M0 人工核验发现**：`InkCanvas` 在书写过程中用**增量廉价渲染**、抬笔才切到拟合几何，导致**抬笔前比抬笔后粗糙**。改为湿态也自绘后，湿/干走**同一条渲染路径**，抬笔零跳变。实测每帧重建代价 0.11~0.83 ms（60Hz 帧预算的 0.6%~5.0%），完全可行。详见 `M0进展报告.md` §六-D |
| **图形与几何** | WPF `StreamGeometry` / `Geometry.Combine(Exclude)` | 内置布尔差集，替代 SkiaSharp 的 `PathOp.Difference`，且零原生依赖；图形同样走平滑风（无抖动） |
| **JSON** | `System.Text.Json`（内置） | 零依赖 |
| **压缩** | `System.IO.Compression`（内置） | `.wb` 包格式 |
| **第三方插件运行时** | **纯托管脚本沙箱（Jint / JavaScript）** | 零原生依赖 → 同时满足 C1/C3；WASM 待 PoC（见 §4.3） |
| **不使用** | Avalonia、SkiaSharp、WinUI3/Windows App SDK、Electron/Tauri、WebView2、任何需要 VC++ 运行时的库 | 分别违反延迟、C1、C1/C2 |

### 2.1 关键不变量（可自动化审计）

> **I1 · 发布目录零第三方原生库**
> 发布目录中除 .NET 自包含运行时自身的文件外，**不得出现任何第三方 `.dll`**。
> 审计方式：维护 `known-runtime-files.manifest`，CI 比对发布目录，多出的文件即告警。

> **I2 · 数据自包含**（C3，已按决策 D3 细化）
> - **程序产生的所有数据文件**（配置、缓存、日志、自动保存、插件数据、用户未指定路径时保存的画板文件）**必须位于 exe 同级目录或其子目录内**；对其它任何位置零写入（含 `%TEMP%`、`%APPDATA%`、`%LOCALAPPDATA%`）。
> - **唯一例外**：**用户显式发起的保存 / 导出**（点「保存」到已知路径、点「另存为」、导出 PNG）可写到**用户选择的任意位置**——这是用户的明确意图，风险由用户承担，应用不阻拦。
> - 用户未指定路径时，应用**主动补默认值而不阻塞**：默认落 `<exe同级目录>\data\documents\`，默认文件名为**保存时刻的时间戳**（`yyyyMMdd_HHmmss.wb`）。
> 审计方式：ProcMon 过滤 `WriteFile`/`CreateFile`（排除只读打开），区分「应用自主写入」与「用户会话中保存对话框选定的目标路径」。

> **I3 · 零注册表写入**（含插件运行期）
> 审计方式：ProcMon 过滤 `RegSetValue/RegCreateKey/RegDeleteKey` → 预期 0 条。

> **I4 · 笔迹延迟达标**
> 口径：**应用内延迟 ≤1 帧（16.7 ms），且与裸 `InkCanvas` 基线程序的差值 ≤2 ms**（后者是关键指标——证明我们的分层没有引入额外延迟）。

## 三、部署模型（绿色自包含）

### 3.1 目录布局（单一程序文件夹）

> **部署原则**：整个 `WhiteBoard` 文件夹可**拷贝到任意位置**（本机任意磁盘、U 盘、网络共享、桌面），双击即用。
> **不依赖任何绝对路径、盘符或环境变量**——所有路径一律相对 **exe 所在目录**解析。

```
WhiteBoard\                            ← 程序文件夹，整体可拷贝
├── WhiteBoard.exe                    ← 主程序
├── <~190 个 .NET 运行时与 WPF 文件>    ← 自包含，零外部依赖
├── ext\                              ← ★ 第三方插件（升级时保留）
│   ├── com.vendor.solver\
│   │   ├── plugin.json
│   │   └── plugin.js
│   └── ...
├── data\                             ← ★ 程序产生的全部数据（唯一可写目录，升级时保留）
│   ├── settings.json                 ← 唯一配置文件（非注册表）
│   ├── recent.json
│   ├── documents\                    ← 默认保存位置（用户未选路径时）
│   ├── templates\                    ← 公共模板与默认配置
│   ├── autosave\                     ← 自动保存
│   │   └── <docId>.wb.auto
│   └── logs\
├── docs\                             ← 用户手册
├── 升级.cmd                          ← 只替换程序文件，保留 ext\ 与 data\
└── 验证.cmd                          ← 一键免环境自检
```

**单一数据目录，不做多用户隔离**：全部数据集中在 `data\` 下（同一台机器上的所有使用者共用一份配置与最近文件），便于整体备份、迁移与排查。

**默认文件命名**：用户未指定路径时，自动落 `data\documents\`，文件名取**保存时刻的时间戳** `yyyyMMdd_HHmmss.wb`（避免命名冲突、便于按时间排序，且无需用户思考）。

### 3.2 数据目录：固定，无回退链

数据目录**固定为 `<exe同级目录>\data\`**。

**若该目录不可写**（只读介质、权限不足、被安全软件拦截）→ 弹出中文可读提示：「程序文件夹不可写，请把整个 WhiteBoard 文件夹复制到可写位置后重试」，并进入**只读模式**（禁用自动保存与配置写入，顶部显示醒目提示），**绝不静默降级到系统位置**。

> **为什么取消回退链**：一旦回退到 `%APPDATA%` / `%LOCALAPPDATA%`，数据就脱离了程序文件夹，直接违反 C3，并造成"我的文件到底存哪了"的困惑。宁可明确报错，也不要悄悄把数据写散。

### 3.3 绿色便携带来的四条设计约束

| # | 约束 | 原因 |
|---|---|---|
| 1 | **程序产生的所有数据文件落在 exe 同级目录或其子目录内** | C3 硬要求；用户显式保存的画板文件除外 |
| 2 | **禁用单文件发布，采用自包含单文件夹** | 单文件会把原生库解压到 `%TEMP%`（系统位置），启动慢且留下解压物；单文件夹启动快、可完整审计 |
| 3 | **自动保存（默认 60 s + 关键操作后触发）** | 防崩溃与断电；启动时若发现残留自动保存 → 提示恢复 |
| 4 | **全部路径相对 exe 目录解析** | 文件夹可整体拷贝到任意位置；硬编码路径即失效 |

### 3.4 不依赖目标机预装组件的落地规则（C1）

| 对象 | 规则 |
|---|---|
| .NET 自包含运行时 | 使用系统自带 UCRT（Windows 系统组件），**不需要 VC++ 可再发行组件**（M0 阶段用 PE 导入表扫描二次确认） |
| 宿主第三方库 | 一律不引入（见 I1） |
| T2 官方插件 | 只能引用宿主提供 + 纯托管依赖；**禁止任何原生依赖** |
| T1 脚本插件 | 纯文本脚本，天然无原生依赖 |
| 任何原生 DLL（若将来必须引入） | **必须 `/MT` 静态链接 CRT**，且通过预检的 PE 导入表扫描 |

## 四、插件体系（C4：第三方开放）

### 4.1 三通道架构

| 通道 | 面向 | 载体 | 能做什么 | 环境依赖 |
|---|---|---|---|---|
| **T1 · 脚本沙箱**（第三方主力） | 任意开发者 | `.js` 脚本 | 求解器、格式导入导出、滤镜、批量处理、生成图形对象、菜单项、设置面板、注册撤销命令 | **零依赖**（含零原生依赖） |
| **T2 · 进程内程序集**（官方/签约） | 官方与白名单 | `.dll` + 自包含目录 | 全部能力，含新增 `ITool` 与 `ShapeObject` 子类 | 宿主运行时 |
| **T3 · 进程外**（兜底） | 重型/不可信 | 独立进程 + 命名管道 | 重型计算、外部集成；崩溃不影响宿主 | 由插件方决定 |

**为什么 T1 用纯托管脚本引擎而不是 WASM**：WASM 运行时（Wasmtime/Extism/WasmEdge）本身是**原生库**，其 CRT 链接方式需逐一核查，与 C1「不依赖目标机预装组件」直接冲突；而 Jint（纯 C# 的 JavaScript 解释器）**零原生依赖**，天然满足 C1/C3，且同样具备沙箱隔离、无 ABI 问题、无法触碰注册表与文件系统的结构性保证。**WASM 作为 S3 的可选 PoC**（若其原生库确认静态链接 CRT，则在 S4 追加为第四条通道）。

**为什么这个划分符合真实需求**：白板插件需求中约 80% 是"计算与数据"类（求解器、格式、滤镜、批量），T1 全覆盖；只有"新增交互式绘图工具"必须要 T2——而这恰是只有官方/签约伙伴才做得好的事。**需求分布与权限分布天然吻合。**

### 4.2 脚本沙箱（T1）的安全边界

宿主**只注入**以下能力，其余一律不存在：

```js
// 插件可用的宿主 API（示例）
wb.meta                       // 插件自身信息
wb.canvas.createShape(type, props)   // 创建图形对象（返回 id）
wb.canvas.getSelected()              // 读取选中对象（只读副本）
wb.commands.register(name, fn)       // 注册撤销命令
wb.ui.addMenuItem(id, label, fn)
wb.ui.addPanel(id, schema)
wb.math.eval(expr) / solve / sample  // 宿主提供的数学原语（C# 实现，性能好）
wb.data.readText(relPath)            // 仅限 data\ 目录内，宿主做路径校验
wb.log.info(msg)
```

**不存在**：`System.IO`、`System.Net`、`Registry`、`Process`、`Assembly.Load`、任意 P/Invoke。

**配额与看门狗**：Jint 的 `Options.TimeoutInterval`（单次调用超时）、`MaxStatements`（语句数上限）、`LimitMemory`、`LimitRecursion`；超限即终止该插件调用并记录，**绝不影响宿主**。

### 4.3 插件包格式与安装

```
com.vendor.solver.wbp          ← ZIP 包，拖入宿主窗口即安装
├── plugin.json
├── plugin.js                  ← T1 主体
├── icon.svg
├── i18n/zh-CN.json
└── LICENSE.txt
```
- **安装 = 拖入或解压到 `<exe同级目录>\ext\<id>\`**，无需安装程序、无需管理员、无需重启
- **卸载 = 删除目录**（脚本插件可热卸载；T2 用可回收 ALC 卸载）

### 4.4 `plugin.json` 清单

```json
{
  "id": "com.vendor.solver",
  "name": "方程求解器",
  "version": "1.0.0",
  "apiVersion": "1.0",
  "hostMinVersion": "1.0.0",
  "runtime": "script",                    // script | inproc-dotnet | outproc
  "entry": "plugin.js",
  "capabilities": ["solver", "menu", "panel", "command"],
  "permissions": [],                      // 声明式权限，默认全空
  "targetFramework": null,                // T2 必需
  "hostProvided": [],                     // T2 必需
  "nativeDependencies": []                // 应恒为空；非空则触发 PE 扫描

```

### 4.5 预检工具 `wbplugin-verify`（9 项，可自动化 = 可验收）

| # | 检查 | 判定 |
|---|---|---|
| 1 | `apiVersion` / `hostMinVersion` 兼容性 | 不兼容即拒绝 |
| 2 | TFM ⊆ 宿主提供（T2） | `net10.0` 以外拒绝 |
| 3 | 托管引用 − `hostProvided` 差集 | 差集非空即拒绝，并列出缺失文件名 |
| 4 | IL 扫描所有 P/Invoke | 与 `nativeDependencies` 比对，缺一即拒绝 |
| 5 | **PE 导入表扫描** | ⭐ 见下 |
| 6 | 禁用 API 扫描 | `Registry` / `System.Net` / `Process` / `Assembly.LoadFrom` / `Environment.Exit` |
| 7 | 夹带 `hostProvided` 程序集 | 有即拒绝 |
| 8 | 签名校验（官方插件强制） | 签名不符即拒绝 |
| 9 | `permissions` 与实际调用比对 | 未声明的能力被调用即拒绝 |

**⭐ 第 5 项：PE 导入表扫描（直接回答"无 VC++ 环境能否跑"）**

递归解析插件目录下**所有** `.dll` / `.exe` 的 PE 导入表，逐个判定：

| 导入的 DLL | 判定 |
|---|---|
| `ucrtbase.dll`、`api-ms-win-crt-*.dll`、`msvcrt.dll` | ✅ 允许（UCRT 是 Windows 系统组件） |
| Windows 系统 DLL 白名单 | ✅ 允许 |
| 本机 `System32` 中存在的 DLL | ✅ 允许（属操作系统组件，单独列出以便审计） |
| **其它任何 DLL（含 `msvcp*.dll` / `vcruntime*.dll`）** | ✅ 允许，**前提是该文件就在插件目录内（随包携带）**；未随包携带则 ❌ 拒绝 |

> ⚠️ **M0 实测修正（2026-09-12）**：原规则是"导入 `msvcp*/vcruntime*` **一律拒绝**"，**过严且不正确**。
> 因为 **本地部署（app-local）同样是微软支持的 VC++ 运行时分发方式**——把 `msvcp140.dll` / `vcruntime140.dll` 放进程序（或插件）自己的目录，目标机**无需安装** VC++ 可再发行组件即可运行。
> 因此正确判据是「**依赖是否可解析**」（系统组件 ∪ 随包携带），而不是"是否出现了某类 DLL 名字"。原规则会误杀合法插件。
>
> 拒绝时的提示语也应改为：「插件依赖 `X.dll`，但既未随插件携带、目标机也没有。请把该 DLL 放进插件目录（app-local 部署），或要求目标机安装 VC++ 可再发行组件。」

**这条规则把"插件在无环境主机能否运行"从人工判断变成了机器判定。**

## 五、架构分层（语言无关，七层）

```
L1 外壳   主窗口 / 顶部工具栏(含溢出) / 右侧页面缩略图 / 可折叠数学·化学面板 /
          对话框 / 悬浮球(不抢焦点) / 设置 / 首次运行部署提示
L2 输入   统一指针抽象(鼠标+触摸+笔) / 压感 / 双指缩放平移 / 掌拒 /
          触摸面积→橡皮直径(凸包+鞋带公式)
L3 工具   ITool 状态机 × 14：画笔 直线 矩形 椭圆 三角 多边形 箭头 文本 /
          选择(点选·框选·缩放·旋转·克隆·层级) 橡皮(部分擦除) /
          直尺 量角器 圆规
L4 命令   ICommand + CommandManager：**每页一个独立撤销栈**，撤销只作用于当前页，
          切页不入栈，栈有上限（步数/字节数取小，溢出丢最早）；事务化，支持擦除/克隆
L5 模型   Document → Page[] → ShapeObject[]（局部坐标系 + 旋转矩阵）
          ViewportState / Resources(图片) / ZOrder / 多态序列化
L6 渲染   世界坐标几何 + 变换矩阵 / 可见区裁剪 / **平滑笔迹渲染（含湿态，同一条路径）** /
          几何冻结缓存 / 每帧矢量重绘（支持无损放大） / 高清导出
L7 服务   Math(表达式解析·Brent 求根·Newton 方程组·函数采样) /
          Chemistry(四角标模型与编辑器) / Files(.wb=ZIP 读写·图片·PNG 导出) /
           Plugin Host(契约·脚本沙箱·进程内加载器·预检·管理 UI)
```

### 5.1 四条贯穿全局的设计红线

1. **湿/干笔迹同源渲染**：落笔期间只画在"湿层"（不进文档、不进撤销栈），抬笔时一次性转为 `FreehandObject` 入文档。
   **湿态与干态必须走同一条渲染路径**（都是"重建 `Stroke` → `GetGeometry()` → 几何填充"），否则抬笔时外观必然跳变。
   > ⚠️ **不使用 `InkCanvas` 自带的湿渲染**：它在书写中用增量廉价渲染、抬笔才切到拟合几何 → 实测"抬笔前比抬笔后粗糙"。
   > 这条是低延迟与零跳变的共同前提，也是上次 Avalonia 方案失败的核心教训（渲染路径不可控）。

4. **矢量重绘，禁止固定分辨率位图缓存**（S2「无损放大 50 倍」的前提）：
   几何一律按**世界坐标**构建，缩放平移只改变换矩阵、每帧重绘；
   实测 50x 下边缘过渡宽度 2.71 px（抗锯齿正常），而"位图缓存后放大"路线为 190 px（完全糊掉）。
   导出时用 `pixelsPerUnit` 提高分辨率即可输出高清图。
2. **模型层不依赖 UI 框架**：`Model / Commands / Geometry / Math / Chemistry / Files` 只依赖基础类型与几何原语 → 可单元测试、可换 UI 外壳。
3. **路径与配置全部经统一服务**：所有可写路径由 `PathService` 统一解析（数据目录固定为 `<exe同级目录>\data\`，不可写时报错并进入只读模式），**任何代码不得直接拼盘符或 `%APPDATA%` / `%TEMP%`**。
4. **文本编码统一 UTF-8**（用户侧首选）：程序写出的所有文本文件（`settings.json`、`recent.json`、`color.txt`、`快捷键说明.txt` 等）一律 **UTF-8**；读取时**先剥离 BOM → 尝试 UTF-8 严格解码 → 失败回退系统 ANSI 编码 → 仍失败则用内置默认值**。
   > 理由：主题/配置/说明文件里有中文。用户用记事本编辑后可能存成 ANSI（GBK），若不做编码回退，程序会因解码失败整体回退默认，用户会以为"改了没用"。**写入侧统一 UTF-8，读取侧宽容兼容。**

### 5.2 WPF 特有的两个已知代价（必须在 S1 解决）

| 代价 | 对策 |
|---|---|
| WPF **没有** UWP/Avalonia 式的统一 `PointerPressed/Moved/Released` | 自建 `IPointerSource` 抽象层，把 `Stylus*`/`Touch*`/`Mouse*` 三路统一为 `PointerEvent{Id, Pos, Pressure, Kind}`；顺手把双指手势与掌拒做进去（约 300~500 行） |

## 十、决策记录（ADR 摘要）

| ID | 决定 | 理由 | 替代方案与否决原因 |
|---|---|---|---|
| ADR-01 | 语言用 C# 而非 C++/Rust | 上次失败是框架问题非语言问题；团队熟悉；生态成熟 | C++/Qt：开发成本高、Qt 插件版本锁定；Rust：UI/IME 全自建 |
| ADR-02 | 框架用 WPF 而非 Avalonia | WPF 直连 D3D，笔迹延迟低 1~2 帧；`InkCanvas` 现成 | Avalonia：合成层架构性延迟，正是上次失败主因 |
| ADR-03 | 运行时用 .NET 10 自包含，不用 net48 | 免环境部署：不关心目标机装了哪个 .NET 版本；且只有 .NET 8+ 能在 ALC 层拒绝 `Microsoft.Win32.Registry`（C2） | net48：体积小但版本依赖系统，且拦不住插件注册表访问 |
| ADR-04 | 自包含单文件夹，禁用单文件 | 单文件把原生库解压到 `%TEMP%`（系统位置），启动慢且留下解压物，破坏数据自包含（C3） | 单文件：启动慢、向系统位置写入、难以审计 |
| ADR-05 | 引入零第三方原生库 | C1「不依赖目标机预装组件」；降低插件与部署的依赖面 | SkiaSharp：原生库可能依赖 VC++ 运行时；Win2D：同理 |
| ADR-06 | 第三方插件走纯托管脚本沙箱 | 零原生依赖，同时满足 C1/C3；WASM 运行时本身是原生库 | WASM：待 S3 PoC 核查 CRT 链接方式 |
| ADR-07 | 全部数据集中在 exe 同级目录内；不做多用户隔离 | C3 数据自包含 | `%APPDATA%`/`%LOCALAPPDATA%`：数据脱离程序文件夹，违反 C3；多用户隔离：客户明确不需要 |
| ADR-08 | WebP 默认不支持 | Win10 WIC 无内置 WebP，商店扩展在离线机房不可靠；引入解码库会破坏 I1 | 引入原生解码库：违反 C4/I1 |
| **ADR-09** | **笔迹与图形采用平滑风，放弃手绘抖动风** | ⭐ **PoC-A 实测**：手绘风下湿笔迹（`InkCanvas` 平滑）与干笔迹（自研抖动）差异"非常明显"，抬笔瞬间会"变样子"；改平滑风后，干笔迹用 `Stroke.GetGeometry()` 填充渲染，与湿笔迹**逐像素 0 差异**，问题从根上消失，且省掉自研算法 | 手绘风 + 调参靠拢 + 淡入过渡：只能掩盖不能消除差异，且要长期维护自研平滑/抖动算法。<br>⚠️ **这是对原始需求（"所有图形采用手绘风格渲染"）的变更，已由需求方确认** |
| **ADR-10** | 跨页复制/移动 = **拖动到目录缩略图 + 选择工具圈选**（**S2 实现**）；工具栏按钮为备选入口；**不依赖长按/右键** | 触摸屏上长按与鼠标右键都不方便 → 主入口必须是"拖动 + 按钮"；用选择工具圈选后再拖，配合拖动阈值与"仅选择工具可拖对象"，误拖风险可控 | 推到 S4：太晚；长按/右键主入口：触屏不便；仅靠对话框：不如拖动直观 |
| **ADR-11** | 手掌擦除与掌拒**按工具状态共存** | 语义不冲突（不同工具状态）；原需求明确要求手掌擦除 | 只做掌拒：不满足原需求；只做手掌擦除：书写时会被手掌干扰 |
| **ADR-12** | 方向键**只翻页**，微调用 `Ctrl+方向键` | 课堂上翻页高频且需零歧义；微调属精细操作，可用组合键 | 按"有无选中对象"切换语义：会让老师误操作 |
| **ADR-13** | 第三方插件用「**声明式图形**」新增图形类型（宿主按受限指令集绘制） | 满足原需求"插件可新增图形对象类型"，且不破坏"任何插件在未装运行时的机器都能跑"的硬约束（纯数据 → 无原生代码/无 ABI/可静态校验） | 只允许官方 T2 新增图形：不满足原需求；开放 T2 给第三方：放弃沙箱保证 |
| **ADR-14** | **仅 Windows，且 Windows 10 与 Windows 11 都必须可用**（同一份自包含产物）；不做跨平台 | 用户明确平台范围；.NET 10 自包含 + WPF 在 Win10/11 上均可直接运行，无需预装运行时 | 承诺 macOS/Linux：已明确不做。`WhiteBoard.Core` 保持 UI 无关**仅为可测试性**，不再作为跨平台承诺 |
| **ADR-15** | 笔宽三档定为 **细 3 / 中 6 / 粗 10**（世界单位），并设**屏幕渲染宽度下限 2 px** | 实测 <1.5 px 时最低覆盖率降到 50%（发虚+忽明忽暗），≥2 px 时覆盖率 100%、变异系数 0 | 维持 2/4/8：细档在缩小视图下发虚；加模糊/超采样：与"无损放大 50 倍"冲突 |
| **ADR-16** | 外壳层轻量 MVVM，**画布层命令式自绘不走绑定** | 面板/对话框用绑定提效；画布每帧渲染若走绑定会引入属性变更通知开销 | 全面 MVVM：画布性能受损；不用 MVVM：外壳代码难维护 |
| **ADR-17** | **页面切换不做过渡动画，直接切换** | 用户决策：切页无等待，符合课堂"不打断"；省一个任务（约 2 人日） | 原需求要求"默认 300ms 淡入淡出、可更换/关闭" → **属需求变更**，已记录；多种动画风格价值低 |
| **ADR-18** | 橡皮擦用「**遮罩保留 + 延迟烘焙**」，**不做立即碎片化** | 立即碎片化会把"一笔"变成多个独立对象（实测：200 点被 10 个圆擦过 → **11 段**；1200 点被 40 个圆擦过 → **25 段**），**与"选择工具按笔画选中"的语义直接冲突**，且对象数量爆炸。改为保留原始点集 + 擦除遮罩，渲染时做差集（实测最坏 **1.07 ms**，且仅在遮罩变化时重算） | 立即碎片化：选中粒度碎、对象膨胀、撤销是"1→N 替换"；不做擦除：不符合需求 |
| **ADR-19** | 触摸手势按**手势判定窗口**分界：第二指在笔画开始后 ≤150 ms 且 ≤6 点时**取消笔画并进入手势**，超出则忽略 | 第一指按下即开始笔画，若"笔画中一律忽略第二指"会导致**两指手势永远无法触发**（编码时由单元测试发现）；若延时等待第二指又会给单指书写引入起笔延迟 | 纯"忽略第二指"：手势失效；纯"延时判定"：书写有延迟。**笔不参与手势，不受影响** |
| **ADR-20** | **笔迹不平滑：按采样点直接连线（圆角连接），不使用 WPF 的整条曲线拟合**（`FitToCurve = false`） | 实测（`tools\InkStabilityProbe`，60 点、采样间距约 21 px）：采用整条曲线拟合时，**每追加一个采样点都会让整条曲线重算**，变化波及到离笔尖 **78.6 px** 之外，平均每次改动 **241** 个像素——用户描述为“画迹会飘，已经画过的地方还在动”。改为直接连线后，变化被限制在笔尖 **33.3 px** 内（就是笔尖底下那个连接处），平均每次 **122** 个像素，**已经画过的部分一个像素都不动** | 曲线拟合更圆润，但“我画在哪里就是哪里”对书写体验更关键；采样点足够密（60~133 Hz，间距 2~5 px），圆角连接下看不出棱角。可用 `--smooth` 启动参数切回旧行为做同机对比 |

| 3 | 锁定插件 API 契约草案（v0.1，S3 前不实现但先定形） | 第 2 周 | `IPlugin` / `PluginContext` 接口草案 |
| 4 | 编写 S1 详细任务分解与排期 | 第 1 周 | 见 `计划书_S1_基础版.md` |

> **M0 是止损闸门**：若四项 PoC 中任一项不达标，先调整技术基线再进入 S1 主体开发，避免重蹈"做完才发现框架选错"的覆辙。
