## 三、本批新增

### 3.1 页面外壳（本轮）
- **`src/WhiteBoard.Core/Commands/PageCommands.cs`**：5 类页面级命令，全部可撤销。
  - `AddPageCommand` / `DuplicatePageCommand` / `RemovePageCommand` / `MovePageCommand` / `MoveObjectsToPageCommand`；
  - **页面对象只创建一次**：新建页 → 在上面画 → 撤销 → 重做，画的内容一起回来（而不是给一张空页）；
  - **删除最后一页被拒绝**（而不是"悄悄补一页"，那样撤销无法还原）；
  - 跨页搬运**保留世界坐标**（两页共享同一坐标系，搬过去不跑位），并把目标页里的 Z 序排到最上层
    （否则可能被目标页已有内容盖住，看起来像"搬丢了"），撤销时原 Z 序一并还原。
- **`src/WhiteBoard.Rendering/Export/ThumbnailRenderer.cs`**：缩略图渲染。
  复用**同一个** `PageRenderer`（缩略图与主画布结构上不可能不一致）、按内容裁剪取景、
  空页给 4:3 固定取景（不会是 0×0 或一条线）、结果 `Freeze()` 后可安全复用。
- **`CanvasHost`**：`GoToPage` / `GoToPreviousPage` / `GoToNextPage`（切页时清选中 + 重置输入链）、
  `MoveSelectionToPage`、`PageChanged`/`ContentChanged` 事件，以及**拖出画布**的钩子
  （指针拖到画布外时先**取消这次实时移动**再交给窗口判断落在哪个缩略图上——
  否则对象会停在半路：既没回原位，也没搬过去）。
- **`MainWindow`**：左侧页面目录（缩略图 + 黄框当前页 + 页数）、新建/复制/删除/上一页/下一页/移到…、
  **缩略图节流刷新**（450ms，书写时不要每笔都重渲染）、跨页拖放（DragDrop + 按屏幕坐标命中缩略图）、
  **状态栏「撤销页面操作」按钮**。

**为什么页面操作不走 Ctrl+Z**：Ctrl+Z 的语义是"撤销**当前页**上的操作"（ADR：每页独立撤销栈）。
把页面结构操作混进去，会出现"切到别的页之后 Ctrl+Z 撤销的是另一页的删除页动作"这种怪事。
所以单独给一个明确入口，撤销目标一目了然。

### 3.2 文本工具（本轮）
- **`TextObject`**（Core）：文本内容 + 字号（世界单位）+ 字体 + 粗体/斜体；
  `IsErasable = false`（基线要求：橡皮跳过文本）；**尺寸由外部测量后存进来**，
  因为 Core 不依赖任何文字引擎（要能离屏单测）；局部原点 = 文本框左上角。
- **`TextGeometry`**（Rendering）：测量与几何构建**共用同一个 `FormattedText`**，
  因此"编辑框里的大小"与"提交后渲染的大小"必然一致，不会提交瞬间跳一下。
- **`TextTool` + `ITextEditHost`**：工具只负责"该在哪儿开始编辑"，
  宿主（UI 层）负责把 `TextBox` 摆到位、收 IME、提交成对象。
  这样文本工具本身**可以离屏测试**（用假宿主断言"点空白=新建""点已有文字=改那一段"）。
- `SetTextCommand` / `SetTextStyleCommand`：改文字**连尺寸一起改**，
  否则选中框、命中测试、视口裁剪都会用旧尺寸（"框比字小一圈""点了选不中"）。
- `.wb` 格式新增 `text` 类型 + 文字字段（`text/fontSize/fontFamily/bold/italic`）；
  **尺寸直接从文件读、不重新测量**——换机器/换字体版本时重测会让老文件的排版漂移。
### 3.3 追加导入（本轮）
AppendDocumentCommand：把另一份 `.wb` 的所有页追加到当前文档末尾。三个必须做对的地方：
- **Id 全部重分配**（页 Id 与对象 Id 都取自目标文档的分配器）——撞号的后果是渲染缓存按 Id 索引时张冠李戴；
- **深拷贝**——源文档是"别的文件"，不能被这次导入改动；
- **一次可撤销**——导错了整体退掉，而不是一页页删。
导入页在目标文档里按原顺序追加，完成后自动切到第一张导入页（用户立刻看到结果）。
回归用例 7 项，含"把真实保存出来的 `.wb` 导回来"的端到端用例。

## 四、测试抓到的真实缺陷（已修）

### 4.1 命令层：构造时快照 vs 执行时机（第一批）
`Test_Command_Transaction_UndoReverseOrder` 失败，暴露命令层一个经典错误：

> **若在构造函数里就把"目标状态"算好，而多条命令是"先全部构造、再依次执行"（事务化场景），后面的命令会基于过期状态算出错误目标。**

实测表现：`Move(+10,0)` 与 `Move(0,+20)` 先后执行后，**X 被第二条命令覆盖回 0**。
**修法**：引入 `CommandBase`——子类在 `Capture()` 里只捕获一次（首次 `Do()` 时）。
同类问题也存在于 `ZOrderCommand`、`AddObjectCommand`/`CloneCommand`、`ClearPageCommand`，已一并修正。

### 4.2 渲染层：水平笔迹会被视口裁剪整条丢掉（本轮，影响可见画面）
写导出用例时发现：一条**水平**笔迹的采样点包围盒高度是 **0**，
而 `FreehandObject.LocalBounds` 当时只取采样点包围盒、**没有算上笔宽**。后果有两层：

1. **视口裁剪**：可见区域只覆盖笔迹上半部分时，`IntersectsWith` 判定为不相交 → **整条笔迹不画**。
   用户表现为"我只是平移了一下，笔迹就消失了"。
2. **导出**：内容包围盒退化成一条 1 像素高的线。

**修法**：`LocalBounds` 四周外扩 `PenWidth/2`（笔迹的可见范围本就是中心线 ± 半个笔宽）。
回归用例：`Test_Export_ThickHorizontalStrokeIsNotDegenerate`、`Test_Freehand_WorldBounds_IncludesPenWidth`。

### 4.3 导出：内容过小会产出 1×1 像素的图（本轮）
一个点、一条极短的线，内容包围盒接近 0 → 导出成 1 像素高的条。
**修法**：`PngExportOptions.MinSide`（默认 64px），内容过小时按最小边长补足世界矩形。

### 4.4 WPF 快捷键：无修饰键的字母/数字不能做成 KeyGesture（本轮）
`new KeyBinding(cmd, Key.D1, ModifierKeys.None)` 会抛
`NotSupportedException：KeyGesture 尚不支持"None+D1"键和修饰符组合`，
而且是在**窗口构造时**抛出 → 程序直接起不来。
**修法**：裸键（F11、1~5 选工具）改在 `OnKeyDown` 里处理，并避开焦点在输入框的场景。

### 4.5 `App.xaml` 的 `StartupUri` 让无界面入口也构造主窗口（上一轮）
`--self-test` / `--render-smoke` 本该完全无界面，但 WPF 会照着 `StartupUri` 构造 `MainWindow`。
之前没暴露问题只是因为构造没抛异常；4.4 一抛出就让自检入口也崩了。
**修法**：去掉 `StartupUri`，主窗口在 `App.OnStartup` 的"正常启动"分支里显式创建。

### 4.6 拖动移动后撤销回到"拖动后的位置"——等于撤销失效（本轮，最隐蔽）
为了让拖动**实时跟随**，选择工具在移动过程中直接改对象坐标；
抬手时才执行 `MoveObjectsCommand` 补一条撤销记录。
但 `MoveObjectsCommand` 是在**首次执行（Do）时**才捕获起始位置的（见 4.1 的设计），
此时对象已经被实时改到终点了 → 它捕获到的"起点"就是终点 → 撤销什么也不做。

**修法**：抬手提交时**先把对象还原到按下时的位置，再执行命令**。
中间这一步在同一帧内完成，用户看不到，但撤销/重做都正确。
回归用例：`Test_Select_DragMoveIsUndoableBackToOriginalPosition`（同时断言重做回到终点）。

### 4.7 框选漏掉抬手那一点 & 圈选被误判成"误触"（本轮）
两个都出在框选的收尾判定上：

1. `CommitMarquee` 只用移动过程中记录的点，**不含抬手位置**。
   用户把框拖到 A 点抬手，如果最后一次 Move 事件停在 B 点，选中的范围就比看到的框小一圈，
   框内靠近边缘的对象会被漏掉。**修法**：提交前先追加上抬手位置。
2. 判定"这次拖动够不够格算框选"用的是"起点到抬手的距离"。
   **圈选是闭合的**：起点与终点几乎重合，于是整个圈被当成手抖丢掉，圈选永远选不中任何东西。
   **修法**：改用**轨迹包围盒的尺寸**判定（`IsMarqueeBigEnough`），两种模式都成立。

回归用例：`Test_Select_LassoSelectsEnclosed`、`Test_Select_MovingMultipleObjectsTogether`。

### 4.8 删除前面的页会把"当前页"带跑偏（本轮）
`RemovePageCommand` 第一版把当前页索引直接设成"被删掉的位置"：
```csharp
Document.CurrentPageIndex = Math.Clamp(_removedAt, 0, Document.Pages.Count - 1);   // 错
```
删的是**第一个**页时它就跳到第 0 页，而用户当时可能停在第 3 页——
表现是"我明明在第 3 页，删了第 1 页之后画面换成了别的内容"，而且很难意识到原因。

**正确规则**（已修）：
- 删在当前位置**之前** → 当前页索引减一（跟着前移，停在**同一页内容**上）；
- 删的**就是**当前页 → 索引不变（显示原来的下一页）；
- 删在当前位置**之后** → 索引不变。

回归用例：`Test_RemovePage_KeepsSamePageSelectedWhenPossible`（同时断言撤销后仍停在同一页）。

### 4.9 点文字中间选不中它（本轮）
`HitTester` 原先对文本也走"字形墨迹"判定（`FillContains`）。
但**字形之间有空白**——两个字中间就有一条竖缝，于是：

- 用户点在文字正中却选不中它；
- 更糟的是**文本工具**：它用同一个命中测试判断"是不是点在已有文字上"，
  判不出来就在原地**又叠了一段新文字**，看起来像"文字被复制了一份"。

**修法**：文本按**文本框**判定命中（含容差），而不是按墨迹——
文本在交互上本来就是一个"方框对象"，与用户心理模型一致。
回归用例：`Test_TextTool_ClickOnExistingTextEditsIt`、`Test_Text_IsClickable`。

### 4.10 文本编辑浮层吃掉了全部指针输入（**用户实测发现，最严重**）
为了做文本工具，我在画布上面叠了一层用于就地编辑的浮层：

`xml
<Grid>
  <wb:CanvasHost x:Name="Board" />
  <Canvas x:Name="EditorLayer" Background="Transparent">   <!-- ← 就是这里 -->
    <TextBox x:Name="TextEditor" ... />
  </Canvas>
</Grid>
`

`Background="Transparent"` 让这层 Canvas **参与命中测试**。它盖在 CanvasHost 之上，
于是所有鼠标/触摸/笔事件都被它吃掉——**画笔、直线、矩形、椭圆、橡皮全部画不出东西**，
只有工具栏按钮还能点。

为什么之前没发现：那一轮的全部自检（`--render-smoke` 14 项、`--file-smoke` 21 项、218 个单元测试）
**都是离屏的**——它们证明"能渲染、能存读、能算对"，但**证明不了"指针事件真的送到了画布上"**。
单元测试直接构造 `PointerSample` 喂给 `ToolDispatcher`，正好把这一层完全绕过去了。

**修法**：`Background="{x:Null}"`。画布自身不参与命中测试，它里面的 TextBox 仍然可点。

**防回归**：新增 `scripts\ui-tools-test.ps1` 并接进 `verify.ps1` 第 8 步——
真的用 `SetCursorPos` + `mouse_event` 画一笔、用 `keybd_event` 切工具，
逐项断言"画布上出现了像素"，9 项检查覆盖画笔/矩形（含空心）/椭圆/橡皮（含擦回背景）/文本/Esc/Ctrl+Z。
无交互式桌面时如实报告"跳过"而不是假装通过。

### 4.11 笔迹会"飘"：WPF 的整条曲线拟合让已画部分跟着新采样点动（**用户实测发现**）
`DrawingAttributes.FitToCurve = true` 会让 `Stroke.GetGeometry()` 对**整条点集**做一次曲线拟合。
每来一个新采样点，整条曲线都会重算 —— 用户看到的就是"笔已经走过的地方还在动"。

**量化**（`tools\InkStabilityProbe`，60 点、平均采样间距约 21 px、笔宽 6）：

| 方案 | 每次追加改动的像素 | 变化波及到离笔尖多远 | 已画部分 |
|---|---:|---:|---|
| 整条曲线拟合（旧） | 241 | **78.6 px**（近 4 个采样间距） | 会移动 |
| **按采样点直接连线（现默认）** | 122 | **33.3 px**（就是笔尖底下那个连接处） | **一个像素都不动** |

**修法**：`SmoothGeometryBuilder.Smoothing = FreehandSmoothing.None`（`FitToCurve = false`），
实时预览与干笔迹共用这一个设置，因此抬笔仍零跳变。想对比旧手感可用 `--smooth` 启动。

**防回归**：`StrokeStabilityTests` 7 项。其中 `Test_Freehand_GuardDetectsWholeCurveFitting`
是**自证用例**——它临时切回旧的整条拟合，断言"旧行为确实超出 50 px 阈值"，
以此证明那条阈值不是随便定的（阈值 50 px 介于实测的 78.6 与 33.3 之间）。

### 4.12 拖动在真实鼠标下有两处走不通（**用户指出"拖动还没做"，实测确认**）
`scripts\ui-drag-test.ps1`（真鼠标拖 4 条路径）把问题钉了出来：

1. **画布没有捕获鼠标** → 指针一离开画布，WPF 就把后续事件发给光标下的元素，
   画布**再也收不到 Move**。于是"把选中的对象拖到左侧缩略图"这个手势
   **根本走不完**：`IsOutsideBounds` 永远不成立，跨页搬运的回调一次都不会触发。
   **修法**：鼠标按下开始交互时 `CaptureMouse()`，抬起时释放（中键平移有独立捕获，需互不干扰）。
2. **拖出画布后第一次没落在缩略图上就取消拖动**。
   人拖动的真实轨迹是"先越过画布左边界，再挪到缩略图上"，
   越过边界那一下几乎不可能正好压在缩略图上 → 拖动被取消，用户感觉"拖了没用"。
   **修法**：没命中缩略图时**不打断**这次拖动，让它继续跟着指针走。

另外补上了两件"有实现没入口"的事：**克隆对象**（`CloneCommand`）与
**把当前笔宽应用到选中的笔迹**（`SetPenWidthCommand`），以及**拖动缩略图调整页序**（`MovePageCommand`）。

回归防护：`verify.ps1` 第 9 步 = `ui-drag-test.ps1`（6 项：拖动对象 / 中键平移 / 跨页搬运 / 页序调整 / 两条"是移动不是复制"）。
