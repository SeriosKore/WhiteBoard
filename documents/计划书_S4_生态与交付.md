# 计划书 · S4 生态与交付收尾

> 上游基线：`白板开发总路线.md`（v1.0）· 前置：S3 出口准则全部满足
> 期目标：**从"能跑"到"能卖、能批量部署、能长期维护"**
> 工期：**8 周 · 2 人**（≈16 人周 / 3.7 人月）

---

## 一、期目标

1. 补齐插件生态的**可信与可运营**能力（签名、白名单、集中部署、准入规范）；
2. 若 S3 的 WASM PoC 通过 → 追加**第四条插件通道**；
3. 完成**批量部署工具**，让机房管理员一次部署多台机器；
4. 国际化、稳定性收尾、文档交付，形成**可验收的完整交付物**。

---

## 二、范围

### ✅ 本期做

| 分类 | 内容 |
|---|---|
| WASM 通道（条件） | 若 S3 PoC 通过：接入 WASM 运行时，作为第四条通道；同步扩展预检规则 |
| 插件可信 | 插件签名（`plugin.json` + 目录哈希清单）、官方认证标记、白名单策略（可配置为"仅官方/仅签名/全部"） |
| 插件运营 | 插件市场准入规范文档、质量清单、版本与兼容性矩阵、离线插件仓库目录结构 |
| 集中部署 | `<程序文件夹>\ext\` 批量分发脚本；`部署.cmd`（支持多机/网络路径/增量） |
| 升级工具 | `升级.cmd`：只替换程序文件，保留 `ext\` 与 `data\`；升级前自动备份 |
| 国际化 | 中/英双语（资源文件 + 切换 + 插件 i18n 加载） |
| 稳定性 | 长时运行（8 h）、内存泄漏排查、极端文档（5000 对象）、异常恢复演练 |
| 无障碍与效率 | 全功能快捷键、Tab 导航、高对比度主题 |
| 文档 | 用户手册、教师快速上手指南、部署手册、插件开发者文档站、培训材料 |
| 合规 | 最终合规证据包（I1~I4 全量证据 + 验收报告模板） |

### ❌ 本期不做

- 联网自动更新（违反"不联网/零注册表"约束，明确不做）
- 云同步、账号体系（不在需求内）

## 六、出口准则（项目验收准则）

1. D1~D11 全部通过；
2. **最终合规证据包**通过客户验收（含注册表、exe 同级目录外写入、VC++ 运行时依赖、延迟四项硬证据）；
3. 非开发人员按手册独立完成部署 + 一节课使用，无阻断问题；
4. P0/P1 缺陷归零；
5. 插件生态有 ≥1 个真实第三方插件通过全部预检并投入使用。

## 七、风险与对策

| # | 风险 | 等级 | 对策 |
|---|---|---|---|
| R1 | WASM 原生库依赖 VC++，破坏 C1 免环境部署 | 中 | 前置判定不通过即关闭该通道；不影响主交付 |
| R2 | 插件签名与"免安装/免注册"理念冲突 | 低 | 签名只做完整性校验，不依赖注册表与证书存储的写权限 |
| R3 | 升级工具误删用户数据 | 高 | 升级前自动备份 + 只替换程序清单内文件 + 升级后校验 |
| R4 | 长时运行内存缓慢增长 | 中 | 定期压力测试 + 泄漏排查 + 对象池 |
| R5 | 文档与实际行为不一致 | 中 | 文档由非开发人员实操验证后才算完成 |
| R6 | 客户在验收时对"注册表零写入"口径有异议 | 中 | 提前用总路线 §1.1 的三条口径书面确认，附 MUICache 证据说明 |
