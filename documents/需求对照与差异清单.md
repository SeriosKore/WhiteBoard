## 四、决策结果（已由开发方决策，供需求方复核）

> D1~D12 全部已决策并落入对应文档。**任一项如需推翻，说一声即可改**；未推翻即按此执行。

### D1 · 橡皮擦语义 → ✅ 按覆盖面积擦除（已修正）

布尔差集与触摸面积自适应**由 S2 提前到 S1**（新增 T4.7 / T4.8，净增 4.5 人日）。
理由：原需求原文即为"仅删除覆盖区域内的部分"，且"整对象删除"会被当成 bug。
代价：S1 WBS 85.5 人日 / 100，缓冲 14.5%（若 M0 需调基线，S1 顺延 1 周）。

### D2 · 跨页复制/移动 → **拖动 + 选择工具（S2 实现，不推 S4）；不依赖长按/右键**

> 用户修订（2026-09-12）：**触摸屏上长按与鼠标右键都不方便**；拖放**不该推到 S4**。

| 项 | 决策 |
|---|---|
| **阶段** | **S2 实现**（与跨页操作同期），**不再推到 S4** |
| **入口①：拖到目录** | 用**选择工具**选中对象后，**把选中对象拖到右侧目录的目标页缩略图上**（拖动中缩略图高亮）→ 释放即**移动**；按住 `Ctrl` 释放为**复制** |
| **入口②：按钮** | 选中对象后，工具栏/上下文条出现「**移到页…**」「**复制到页…**」按钮 → 弹出页选择对话框（网格缩略图 + 移动/复制单选） |
| **为什么不用长按/右键做主入口** | 触摸屏上长按与右键都不方便；主入口改为**拖动 + 按钮**，长按/右键**仅作鼠标端补充** |
| **选择工具（关键）** | **新增「圈选（套索）」并保留「框选」**：圈住笔画即选中，随后可直接**拖动移动**——这就是"圈住选中笔画再拖动"的操作方式 |
| **防误拖** | ① **只有选择工具激活时才能拖动对象**（画笔/形状工具下拖动 = 绘制）；② 触摸下**双指 = 缩放/平移**，单指才操作对象；③ 鼠标端**按住 `Ctrl` 拖动 = 强制移动选中对象**（与框选区分）；④ **拖动阈值 4 px**（小于视为点击）；⑤ 未选中对象时拖动 = 平移画布 |
| **撤销** | 方案 A：源页/目标页各记一条**配对互引**命令，撤销任一条时同时回滚两侧并自动切回源页 |
### D3 · 手掌擦除 → **与掌拒共存，按当前工具状态切换**

| 当前工具 | 手掌行为 |
|---|---|
| 画笔 / 形状 / 选择 | **掌拒**：笔在感应范围附近，或触点面积超阈值 → 忽略该触点 |
| **橡皮** | **手掌 = 大号橡皮**：面积超阈值即视为手掌擦除，直径按接触面积计算（`clamp(√area×1.6, 60, 420)` px） |

理由：两者语义不冲突（不同工具状态），且原需求明确要求手掌擦除。
⚠️ 阈值需真机调参（无目标机型时先取经验值，S2 在真机上校准）。

### D4 · 方向键冲突 → **方向键只翻页，微调用 `Ctrl+方向键`**

| 组合 | 功能 |
|---|---|
| `←` `→` `PageUp` `PageDown` | 上一页 / 下一页 |
| **`Ctrl+←/→/↑/↓`** | 微调选中对象位置（每次 **1** 世界单位） |
| `Ctrl+Shift+方向键` | 微调 **10** 世界单位 |

理由：课堂上翻页是高频且需零歧义的操作；微调是精细操作，允许组合键。

### D5 · 画布右键菜单 → **做**（S2）

鼠标右键 / 触屏长按呼出。菜单项：复制、粘贴、删除、克隆、置顶、置底、编辑文本（仅文本对象）。与 D2 共用长按机制。

### D6 · 第三方插件新增图形对象类型 → **开放「声明式图形」给 T1 沙箱**

插件不写像素、不调 API，只用**受限绘制指令集**描述图形，由宿主渲染 / 命中测试 / 缩放 / 序列化：

```json
{ "type": "repeat", "count": 5, "rotate": 72, "children": [
  { "type": "polygon", "closed": true,
    "points": [[0,-1],[0.22,-0.3],[1,-0.3],[0.36,0.15],[0.6,0.9],[0,0.45],[-0.6,0.9],[-0.36,0.15],[-1,-0.3],[-0.22,-0.3]] }
] }
```

可用指令：`polygon`（闭合/开放）、`polyline`、`ellipse`、`text`、`repeat`（旋转复制，用于星形/花瓣等对称图形）。

理由：满足原需求"插件可新增图形对象类型"，同时**不破坏**"任何插件在未装运行时的机器上都能跑"的硬约束（纯数据描述 → 无原生代码、无 ABI 问题、可静态校验）。

### D7 · 跨平台 → **只交付 Windows；代码分层强制保留跨平台可行性**

- **交付范围**：仅 Windows 10 x64（WPF 不跨平台）。
- **强制约束**：`WhiteBoard.Core` 只依赖 `net10.0`（**不带 `-windows`**）与跨平台 API；任何 Windows 专有调用必须封装在 `WhiteBoard.App` 内。
- 收益：未来若换 UI 壳，模型层 / 服务层可原样复用 → **零成本保留选项**。

### D8 · MVC / MVVM → **外壳层轻量 MVVM，画布层不用绑定**

- 面板、对话框、页面列表、插件管理 UI → ViewModel + 绑定；
- **画布（`CanvasHost`）保持命令式自绘**，不走绑定（避免每帧属性变更通知与渲染开销）。

### D9 · 平台与发布形态

**平台（用户明确）**：**只考虑 Windows，且 Windows 10 与 Windows 11 都必须能用。**

| 项 | 决策 |
|---|---|
| 交付平台 | **Windows 10 x64 + Windows 11 x64 同一份产物都要可用** |
| 技术保证 | .NET 10 自包含 + WPF → 不依赖目标机预装运行时；`app.manifest` 声明 Win10/11 兼容；DPI 感知 PerMonitorV2 |

| **发布形态**（原 D9 议题） | **保持禁用单文件，用自包含单文件夹**（未收到推翻意见，按推荐执行）。若日后确需单文件，可加 `-SingleFile` 开关，但需接受"首次启动解压到 `%TEMP%`"的代价 |

用户决策：**无过渡动画，直接切换页面。**

### D11 · 细笔锯齿 → **最细档提到 3，并加屏幕宽度下限 2px**

| 措施 | 内容 |
|---|---|
| 笔宽档位 | **细 3 / 中 6 / 粗 10**（世界单位；原 2/4/8 的"细"档在缩小视图下会发虚） |
| 渲染下限 | 世界宽度 × 缩放 < **2 px** 时按 **2 px** 渲染（防发虚与覆盖不均；放大时不受影响） |
| 不做 | 模糊 / 超采样（会与"无损放大 50 倍"冲突） |

依据：实测 <1.5 px 时最低覆盖率降至 50%（发虚 + 忽明忽暗），≥2 px 时覆盖率 100% 且变异系数 0。

- 超大图额外生成缩略图供缩略图栏使用；
- 页面切换、导出复用同一缓存。

### D13 · 擦除的实现路线（用户提出）→ **遮罩保留 + 延迟烘焙**

> 用户指出：**选择工具选中的是"笔画"，而擦除会把一笔切成多笔** —— 两者语义冲突。我没有提前处理这一点。

**问题量化**（实测：一条 200 点笔迹被 N 个擦除圆覆盖后，若立即碎片化会产生多少个独立对象）：

| 点数 | 擦除圆数 | 若碎片化 → 段数 |
|---:|---:|---:|
| 200 | 1 | 2 |
| 200 | 10 | **11** |
| 200 | 30 | **19** |
| 1200 | 40 | **25** |

**决策（ADR-18）：采用「遮罩保留 + 延迟烘焙」**

| 层 | 做法 |
|---|---|
| 模型 | 对象保留**原始点集 / 参数**，另存 `Erasures`（擦除圆的世界坐标列表） |
| 渲染 | `渲染几何 = 原几何 − 擦除遮罩`，**结果缓存**，仅在遮罩或几何变化时重算 |
| 命中测试 | 在**差集后的几何**上做 → 被擦掉的区域点不中 |
| **选中** | **永远选中"那一笔"整体**（含被擦除区域）→ 与选择工具语义一致 ✅ |
| 撤销 | 一次擦除 = 一次遮罩追加 = **一条命令**，撤销即回退遮罩 |
| 拖动 | 整条一起移动 |
| **延迟烘焙** | 遮罩数超阈值（如 32 个）或用户点「**切分为独立对象**」时，才真正切分成多个对象 |
| 序列化 | 对象多一个 `erasures` 字段 |
| 几何形状 | **同样用遮罩**：保留参数化形状 + 遮罩，渲染时差集 |

**实现代价实测**

| 点数 | 擦除圆数 | 路线甲：几何差集 | 路线乙：点集切割 |
|---:|---:|---:|---:|
| 60 | 1 | 0.38 ms | 0.31 ms |
| 200 | 10 | 0.54 ms | 0.06 ms |
| 600 | 20 | 0.67 ms | 1.32 ms |
| 1200 | 40 | **1.07 ms** | 0.09 ms |

→ 几何差集最坏 **1.07 ms**，且**仅在遮罩变化时**重算一次 → 完全可行。

## 六、细笔锯齿的实测与分析

**你的反馈**：笔越细锯齿越严重。

**实测**（浅斜线，逐列取最大覆盖率；CV = 变异系数，越小越均匀）：

| 渲染线宽 | CV | 最低覆盖率 | 判定 |
|---:|---:|---:|---|
| 1.0 px | 0.200 | **50%** | ❌ 发虚 + 覆盖不均（锯齿感强） |
| 1.5 px | 0.092 | 75% | ⚠️ 偏虚 |
| **≥2.0 px** | **0.000** | **100%** | ✅ 完全实心、均匀 |

**另外实测结论**：**"轮廓填充"与"中心线描边"在直线段上完全等价**（同一区域，逐像素 0 差异），所以细线问题与渲染方式无关。

**分析**：细笔的锯齿感有两个来源——
1. **≲1.5px 时抗锯齿覆盖不足** → 线发虚、忽明忽暗（上表前半段）；
2. **≥2px 时覆盖已完美**，但"像素阶梯相对线宽的比例"仍随线宽减小而变大（2px 线走斜线时，1px 的阶梯占了线宽的一半，视觉上就是锯齿）。

第 2 条是**几何本质**，不是渲染缺陷；放大后自然消失（矢量无损）。

**建议（D11）**：
1. **"细"档由 2 提到 3 世界单位**（成本 0，视觉改善明显）；
2. 加**渲染屏幕宽度下限 2px**（防止缩小视图时线发虚、覆盖不均）；
3. 不做额外的模糊/超采样（会与"无损放大"目标冲突）。
